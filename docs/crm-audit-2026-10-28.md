# CRM 검증 기록 — 2026-10-28

관련 이슈: AX-1150, AX-1325, AX-1326, AX-1327, AX-1328, AX-1329, AX-1330.

## 결론

변경 기능의 집중 테스트는 통과했지만 전체 회귀 테스트, 전체 타입 검사 및 브랜치 lint에는 실패가 남아 있다. 서비스 전체의 무결함 또는 배포 승인을 의미하지 않는다. 운영 발송, 결제, 부하 테스트와 외부 침투 테스트는 수행하지 않았다.

## 이번에 수정한 결함

- 표준 앱 동기화가 사용자 정의 탭을 참조하는 위젯을 `PAGE_LAYOUT_TAB_NOT_FOUND`로 거부했다. 전체 워크스페이스를 검증 의존성으로 제공하되 마이그레이션 대상은 표준 앱으로 제한했다. 빌더의 변경이 캐시에 영향을 주지 않도록 의존성 맵을 복제한다. 로컬 dry-run과 실제 동기화를 확인했다.
- 쿠폰 견적 이후 고객 분류 접근 권한이나 수신자가 변경되어도 예전 대상으로 발송될 수 있었다. 실제 주문 전에 현재 권한·목록·전화번호를 다시 검증하고 차이가 있으면 재검토를 요구한다. 권한 회수 및 수신자 변경 테스트를 추가했다.
- 고객 분류 명칭은 코드뿐 아니라 기존 객체·뷰·탭·위젯·표시용 override를 워크스페이스 범위에서 변경하도록 마이그레이션을 추가했다. 트랜잭션 롤백 및 dry-run을 테스트했다.

전체 회귀 수치는 최종 수정 전 실행 기록이다. 이후 변경 관련 테스트만 다시 실행했다. 표준 객체 ID 스냅샷 실패 1개는 실제 메타데이터와 재대조하여 갱신하고 집중 테스트로 통과를 확인했다. 해당 스냅샷에는 새 avatar 필드 외에 기존 정의와 누락된 필드의 정합성 갱신 및 순차 mock ID 이동도 포함된다.

프론트 실패는 필터 초기화, 워크스페이스 생성 로고, 레코드 생성·조회·수정 훅, GraphQL 필드 스냅샷에 걸쳐 있다. 서버 실패는 검색 필드 backfill, IMAP/SMTP, Microsoft 메시지 조회, universal property 스냅샷 등에 남아 있다. 타입 오류는 차트 필터/드릴다운/날짜 유틸 및 서버 메타데이터 fixture·메시징 null 처리 등 이번 변경 밖의 파일에서 발생했다. 깨끗한 기준 커밋과 같은 환경의 비교 실행을 하지 않았으므로 모두 기존 결함이라고 단정하지 않는다.

## UI 및 로컬 데이터 검증

- 고객 분류 메뉴·목록·상세·관계 필드 명칭을 확인했다.
- 상세 이모지와 색상을 저장하고 새로고침 후 유지되는 것을 확인했다. 테스트 후 기본값으로 복원했다.
- 793px 화면에서 작성 패널이 오른쪽 화면 안에 남고 가운데 영역이 가려지는 것을 확인했다. 390px에서는 전환 애니메이션 이후 전체 화면 작성 패널을 확인했다.
- 쿠폰은 인증 미설정 시 검증 모드이며 실제 발송을 사용할 수 없다. 실제 번호 발송이나 유료 주문은 하지 않았다.
- 자금 흐름은 사용자 승인 기준(완료 제외, 분할 잔금 중복 제외, 이번 달 H열 계획)을 원본과 대조하고 로컬 스냅샷에 반영했다. 원본 및 금융 데이터는 Git에서 제외했다. 실시간 은행 조회나 시트 자동 동기화 기능은 아니다.
- 서버 재컴파일 중 일시적인 `Failed to fetch`가 있었고 서버 기동 후 화면을 다시 확인했다. 가캠 매출 외부 연동 오류는 별도 환경 확인이 필요하다.
- 비인증 쿠폰 metadata 요청은 Forbidden, 자금 흐름 REST 요청은 403, healthz는 200을 확인했다. 실사용자 계정 간 교차 워크스페이스 통합 테스트까지 수행한 것은 아니다.

## 의존성 보안 검토

`yarn npm audit --all --recursive --environment production --json` 결과는 critical 14, high 115, moderate 97, low 21의 총 247개 advisory 항목이다. 중복 경로와 모노레포의 문서·개발 도구가 포함되어 있으며 CRM 운영에서 악용 가능한 취약점 247개라는 뜻은 아니다. 이번 작업에서는 의존성 버전을 변경하지 않았다.

우선 확인할 항목:

1. **proxy-addr 2.0.7**: Express 서버 의존성이며 신뢰 프록시 처리에 영향이 있다. 실제 프록시 경로와 IP 기반 제한에 대한 영향 확인 및 패치가 필요하다. [공식 advisory](https://github.com/advisories/GHSA-jqcg-44mw-7w3h)
2. **DOMPurify 3.4.11**: 서버의 HTML 정제 경로에서 사용한다. 보고된 우회에는 특정 옵션·입력 조건이 필요하며 운영 경로의 악용 가능성은 입증하지 않았다. [공식 advisory](https://github.com/advisories/GHSA-cg2g-xh64-v4q7)
3. **Handlebars 4.7.9**: 전이 의존성이다. 신뢰할 수 없는 AST를 컴파일하는 경로의 존재를 추가 확인해야 한다. [공식 advisory](https://github.com/advisories/GHSA-8r5x-fm3f-whwj)

Next 관련 항목은 `twenty-website`에 해당하며 CRM 프론트(Vite)와 구분한다. Storybook/Vitest 등 개발 도구 항목도 운영 서비스 취약점과 구분한다. 변경 파일을 대상으로 주요 키 형식과 개인 키 패턴을 확인했으나 저장소 전체 이력의 비밀정보 검사를 대체하지 않는다.

## 배포 전 남은 조건

- 전체 회귀·타입·lint 실패 분류 및 해결, 의존성 보안 패치와 회귀 검증.
- 센드비 계정별 인증 정보와 연동 승인 후 개발 환경에서 실제 응답 규격 확인. 주문 결과 불명 상태의 운영 대응 절차 확인.
- 자금 흐름 객체·권한·백업을 운영에 적용하는 별도 절차 수행. 로컬 데이터가 커밋만으로 운영에 복제되지는 않는다.
- 신규 workspace command 및 표준 메타데이터 변경은 `GAINGE_WORKFLOWS.md`의 배포 전 버전·마이그레이션 절차를 수행할 것. 이번 작업은 로컬 커밋이며 push 및 배포는 포함하지 않는다.

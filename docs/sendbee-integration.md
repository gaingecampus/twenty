# 센드비 카카오 쿠폰 연동 (AX-1150)

근거: 2026-10-28 수신한 센드비 `모바일쿠폰 제휴 관련 안내드립니다` 메일의
[공식 Open API v0.8](https://guttural-mouth-47c.notion.site/API-_v0-8-26503bacc2ba80899455e8d7570b131d).

## 계정 정보 발급

문서는 `계약 체결 → 연동 정보 전달 & 브랜드 컨펌 → 개발서버 연동 완료 → 운영서버 연동 완료 → 서비스 오픈` 순서를 안내한다.
셀프서비스 키 발급 URL, AES 키/IV 값, 키 배포 절차는 제공되지 않았다. 이번 회신에도 실제 계정 정보는 없다.
센드비 담당자(info@sendbee.co.kr)에게 아래를 받아야 실제 개발 서버 검증을 진행할 수 있다.

- 개발/운영 각각의 매체코드(mid), AES 키와 IV(각각의 원본 인코딩 포함)
- 인증 문자열의 시간대 및 암호화 테스트 벡터
- KAKAO 발송 승인/발신자명, 브랜드 승인, 테스트 상품·잔액·과금 여부
- 수신번호 필드명: 표 `recvNums` / 예제 `receiveNums` 불일치
- 상태 조회 주소: 본문 `/api/coupon/v1/status` / 예제 `/api/order/v1/getCouponStatus` 불일치
- 수신번호 응답의 암호화 규격(예제는 암호문), 최대 수신자 수·호출 제한
- 주문 응답 유실 시 `orderTrID`로 주문을 확인하는 방법. 문서의 상태 조회는 orderId 또는 transactionId만 받는다.

외부 문의는 이 문서로 준비만 했으며 추가 메일을 자동 발송하지 않는다.

## 관리자 설정

관리자 패널의 Config Variables → `SENDBEE_CONFIG`에서 설정한다. 서버 전용 민감 JSON이며 클라이언트로 키를 보내지 않는다.
다음은 비밀값이 없는 예시다. 기본값 `{}`는 비활성 상태다. 운영 환경파일/배포 구성은 수정하지 않는다.

```json
{
  "enabled": false,
  "workspaceId": "허용할 워크스페이스 UUID",
  "environment": "development",
  "mid": "발급받은 매체코드",
  "keyBase64": "AES 키 바이트를 Base64로 인코딩한 값",
  "ivBase64": "16바이트 IV를 Base64로 인코딩한 값",
  "timeZone": "Asia/Seoul",
  "protocolConfirmed": false,
  "recipientField": "recvNums",
  "statusPath": "/api/coupon/v1/status",
  "senderName": "가인지 CRM",
  "maxOrderAmount": 100000
}
```

위의 시간대·수신번호 필드명·상태 주소는 업체 확인 전 예시이며, 임의로 승인 처리하지 않는다.
키는 16/24/32바이트, IV는 16바이트를 지원한다. 업체에서 hex/UTF-8로 제공하면 **원본 바이트**를 Base64로 변환해 입력한다.
인증: AES-CBC PKCS padding, `{mid}|yyyyMMddHHmmss` → Base64. 별도 Bearer 접두어 없음.
개발 주소는 `https://dev2.giftting.co.kr:36710`, 운영은 `https://api.sendbee.co.kr`로 고정한다.
`sendNumber`는 승인받은 번호를 선택적으로 지정할 수 있다. 생략 시 문서의 센드비 기본번호를 사용한다.
업체 확인 및 개발 검증을 마친 후에만 `protocolConfirmed`, `enabled`를 활성화한다.
`maxOrderAmount`는 **주문 1회당 한도**이며 계정 일일 예산/잔액 한도가 아니다.

## 구현 동작

- 내부 검증은 기존 샘플 상품만 사용하며 외부 주문을 보내지 않는다.
- 실연동은 서버에서 상품 목록을 조회하고 판매 중인 상품의 가격을 사용한다. 공개되지 않은 잔액 조회 API는 추측해 구현하지 않는다.
- 고객 목록은 호출자 접근권한으로 읽고 전화번호 오류·중복을 제외한다. 워크스페이스 멤버 중 고객 전화번호가 없는 항목은 제외 수에 포함한다.
- 검토는 10분간 유효하며 수신번호 원문은 워크스페이스에 결합된 AES-GCM 봉투로 암호화해 저장한다. GraphQL에는 마스킹 값만 전달한다.
- 최종 확인에는 수신자 수·예상금액·운영/개발 환경을 표시한다. 서버는 가격·판매 상태·예산·계정/발신 설정을 다시 검사한다.
- DB 행 잠금으로 단 한 호출만 SUBMITTING을 저장한 뒤 네트워크 주문을 수행한다. `orderTrID`는 검토 시 생성해 고정한다.
- 타임아웃, 실패 응답, 응답 파싱 실패는 UNKNOWN으로 기록하고 자동 재주문하지 않는다. 프로세스 종료로 SUBMITTING에 남아도 재주문하지 않는다.
- 발송이력의 **센드비 발급 상태 조회**는 조회 API만 호출한다. 쿠폰 발급 전 PROCESSING과 업체 발송완료 SENT, 개별 쿠폰 사용 가능 여부를 구별한다. SENT는 읽음 확인이 아니다.
- orderId가 없으면 orderTrID로 센드비 측에 대조해야 한다. 다른 검토를 만들어 다시 발송하면 별도 주문이므로 먼저 대조한다.
- 쿠폰 바코드/번호 등 유가증권 원문과 업체 오류 원문은 저장하거나 클라이언트에 노출하지 않는다.
- 취소·재발송·잔액 API는 v0.8에 명세가 없어 구현하지 않았다.

## 검증 및 오픈

41개 서버 테스트로 암호화 벡터, 요청 형식, 상품 필터링, 응답 불일치, 동시 요청, 타임아웃·재시작 후 중복 방지, 가격·예산 변경, 접근권한, 마스킹을 검증했다.
공식 개발 계정이 없으므로 실제 센드비 인증·카카오 수신 검증은 미완료다. 모의 HTTP 테스트를 실발송 성공으로 간주하지 않는다.
실제 발송 검증은 업체 개발 환경의 비용/수신 규칙을 먼저 확인하고 지정된 테스트 수신자와 승인된 예산으로만 수행한다.

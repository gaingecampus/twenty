# AX-1327 월간 자금 흐름

대시보드는 `cashFlowSnapshot`에서 한국 시간 기준 이번 달의 최신 백업 식별자를 찾고, CRM `bankTransaction`의 은행별 최종 거래와 같은 `sourceHash`의 `expectedReceipt` 상세 레코드를 직접 조회·집계한다. 저장된 스냅샷 합계는 검증용으로 보존한다. 지출대기액은 CRM `pendingExpense`의 이번 달 현재 데이터를 직접 합산한다. 은행 실시간 연동이 아니며 도움말에서 백업일과 은행별 잔액·최종 거래일을 확인한다. 전사 자금이므로 그룹·구성원 필터를 적용하지 않는다. 누락·권한 오류·미완료 상세 백업은 0원 대신 미확인으로 표시한다.

## 승인된 집계 규칙

- 잔액: 보존된 신한·국민·농협 입출금 내역에서 은행별 최종 거래 시각의 잔액을 합산한다. 행 순서에 의존하지 않는다. 클릭하면 보존된 입출금 전체 목록을 거래일순으로 열고, 행 클릭으로 개별 상세를 연다.
- 입금예정액: 발행 기업 입금 리스트 중 `expectedDate`가 한국 시간 기준 오늘부터 이번 달 말일까지인 항목(오늘·말일 포함). 지난 예정일·다음 달 이후 예정일·예정일 미입력·노란색 완료 행 제외. `inclusionStatus = 포함` 행의 `outstandingAmount`를 서버에서 합산한다. 클릭하면 같은 조건의 근거 목록을 열고, 개별 상세를 확인할 수 있다. 별도 메뉴에는 제외된 원본 행도 보존한다.
- 분할 입금: 그룹별 마지막 누적 잔금(H열) 한 번만 사용한다. 발행액(E)−입금액(G)과 대조한다. 일반 표와 기업명 별칭·일자·금액이 일치한 항목은 중복 제외한다. 모호한 일치는 자동 추측하지 않고 실패시킨다.
- 지출대기액: CRM `pendingExpense.expenseMonth`가 이번 달이며 `scheduledDate`가 한국 시간 기준 오늘부터 이번 달 말일까지(오늘·말일 포함)이고 `sourceRecordType`이 비어 있는 상세 행의 `plannedCashAmount` 합계. 서버에서 해당 조건의 전체 행을 집계하며 원본 보충 행(제목·소계·메모)은 제외한다. 지난 예정일·다음 달 이후 예정일·예정일 미입력 행도 제외한다. 귀속 월이 이번 달이어도 예정일이 다음 달이면 제외한다. `paidAmount`는 차감하지 않는다. 금액을 클릭하면 동일 조건의 근거 목록을 연다. 조회 실패·통화 이상은 0원으로 치환하지 않는다.
- 가용액: 잔액 + 입금예정액 − CRM 지출대기액. 잔액·입금예정액은 최신 백업에 연결된 상세 DB를 사용하고 새로고침은 백업 식별자와 CRM 집계를 모두 다시 조회한다. 은행·시트 자동 동기화는 포함하지 않는다.

예를 들어 한국 시간 2026-10-29에는 예정일이 10월 29일~31일인 항목만
입금예정액·지출대기액에 집계한다. 10월 28일 이전과 11월 1일 이후는 제외하며,
카드 클릭으로 여는 근거 목록에도 같은 날짜 조건을 적용한다.

## 외부 MCP 배치 운영

백업은 외부 에이전트가 Google Sheets/Excel 읽기 도구와 CRM MCP로 수행한다.
CRM 저장소에는 엑셀 추출·직접 DB 반영용 백업 프로그램을 두지 않는다.
아래는 외부 에이전트가 지켜야 할 데이터 계약이며, 자동으로 실행되는 기능이 아니다.

### 매일 실행할 범위

- 매 실행 시작 시 Asia/Seoul의 날짜와 현재 월을 한 번 결정한다. 실행 중 자정이나 월이
  바뀌어도 해당 실행의 기준은 유지한다. 재시도는 원래 실행의 기준 월·원본 버전을 사용한다.
- 기준 월과 이후 월(다음 연도 포함)을 모두 읽어 변경분을 갱신하고 신규만 추가한다.
  이전 실행 이후 새 행만 읽으면 기존 행의 수정·완료 처리를 놓칠 수 있다.
- 지출은 `expenseMonth`, 입금예정은 `expectedDate`, 은행 거래는 한국 시간의
  `transactionAt`으로 범위를 결정한다. 제목·소계·빈 양식은 실제 거래에서 제외한다.
- 기준 월 이전 자료는 수정·추가·삭제하지 않는다. 예를 들어 11월 실행에서는
  10월의 사후 수정과 미반영 자료도 자동 복구하지 않는다. 과거 수정은 별도 보고한다.
- 분할 잔금 검증과 거래가 없는 은행의 마지막 잔액 확인에 필요한 과거 자료는 읽을 수 있다.
- 월이 바뀌면 이번 달 `cashFlowSnapshot` 연결도 확인한다. 파일 내용이 같다는 이유만으로
  새 월의 연결 준비까지 생략하지 않는다.

백업은 기준 월과 이후 월을 보존하지만, 대시보드의 입금예정액·지출대기액은
한국 시간 오늘부터 이번 달 말일까지(오늘·말일 포함)만 집계한다.
백업에 다음 달 이후 자료가 있어도 이번 달 대시보드 합계에는 포함하지 않는다.
기준 월 안의 지난 예정일·완료·중복 제외 항목도 백업에서는 상태를 보존한다.

### 저장 및 반복 실행

- 먼저 대상 워크스페이스와 기존 `bankTransaction`, `expectedReceipt`, `pendingExpense`,
  `cashFlowSnapshot` 객체 및 필드를 확인한다. 없으면 다른 객체에 대체 저장하지 않는다.
- 모든 대상 탭·월 구역과 CRM 조회 페이지를 읽는다. 최신 헤더·완료 표시·수식 계산값을
  확인하고, 읽기 실패나 누락을 0으로 바꾸지 않는다.
- 원화는 CURRENCY의 원 단위 금액 × 1,000,000인 `amountMicros`와 `KRW`로 저장한다.
- CRM `id`와 `backupId`를 유지한다. 원본의 고정 ID 또는 검증된 연결 정보로 항목을
  대응시킨다. 행 번호·행 순서·파일 해시는 거래 식별자가 아니다.
- 고정 ID가 없으면 기존 비교값과 업무 값이 정확히 일치하는 항목만 연결한다.
  동일 거래의 복수 건수를 유지하며, 수정인지 신규인지 불분명하면 임의 생성하지 않는다.
- `backupBaseline`·현재 CRM·새 원본을 비교해 CRM 편집 충돌을 확인한다.
  원본에서 사라진 항목은 자동 삭제하지 않는다. 원본 ID 열을 임의로 추가하지 않는다.
- 업무 값과 백업 연결이 모두 같으면 쓰기를 생략한다. 매일 같은 레코드와 스냅샷을
  중복 생성하거나, 변경 없는 레코드의 백업 시각만 일괄 갱신하지 않는다.
- 새 백업 버전으로 전환할 때는 변경 없는 대상 입금예정 항목도 새 `sourceHash`에
  연결해야 한다. 변경된 행만 연결하면 대시보드 집계에서 일부 자료가 빠진다.
- 원본 행 번호는 CRM에 저장하지 않는다. 원본 문서·탭 링크와 필요한 백업 식별 정보는
  유지하며, `sourceRow` 칼럼을 다시 만들지 않는다.

### 급여 개인정보

입출금의 급여·상여·성과급·퇴직금 대상자 이름은 저장 전에 제거한다.
이름·내용은 `급여 (대상자 비공개)`, 상세는 `급여: 대상자와 원문 비공개`로 처리하고,
은행·날짜·금액·잔액은 보존한다. 비교값·로그·실행 결과·첨부에도 이름을 남기지 않는다.
식별번호는 마스킹한다. 이름만 적힌 거래처럼 급여 여부가 불명확하면 저장 전에 확인한다.
과거 급여 정보 정리는 현재 월 이후 갱신과 별도 작업이다.

### 완료 표시와 실패 처리

- 배치 실행기는 동시 실행을 막아야 한다. 프롬프트만으로 잠금이나 트랜잭션이 생기지 않는다.
- 쓰기 전에 전체 변경 계획과 개인정보·중복·잔금·합계를 검증한다.
- 여러 MCP 호출의 원자성은 보장되지 않는다. 부분 반영 중 불완전한 값을 대시보드에
  완료된 백업으로 공개하지 않도록 `detailsReady` 전환 절차를 확인한다.
- 모든 상세를 저장하고 재조회 검증한 뒤에만 해당 백업의 `detailsReady`를 켠다.
- 쓰기 실패 시 후속 쓰기를 중지하고 성공한 ID·실패 단계·원본 버전을 기록한다.
  응답이 유실된 생성 요청은 저장 여부를 다시 조회한 뒤 재시도한다.
- 무인 실행에서 확인이 필요하면 임의로 판단하지 않고 실패/확인 필요로 종료한다.
  다음 날 실행이 해결되지 않은 부분 실패를 덮거나 완료로 오인하지 않게 한다.
- 결과에는 실행일·기준 월·객체별 추가/수정/변경 없음/제외 건수·금액 검증·과거 보존 여부와
  확인 사항을 남긴다. 새로 동기화한 데이터가 없으면 `변경 없음`으로 보고한다.

### 기존 프롬프트에 적용할 일일 배치 설정

아래 설정은 탭·열 매핑을 포함한 전체 MCP 백업 프롬프트와 함께 사용한다.
이 문서 자체는 스케줄러를 생성하거나 실행하지 않는다.

```text
실행 방식: 외부 스케줄러에서 매일 실행하는 무인 배치.
갱신 기준 월: 실행 시작 시 Asia/Seoul 기준 현재 월(YYYY-MM).
기준 날짜와 월은 실행 중 고정하며, 재시도는 원래 실행의 기준을 유지한다.
현재 월과 이후 전체 범위를 읽어 기존 항목은 변경분만 갱신하고 신규만 추가한다.
지난달 이전 데이터는 변경하지 않는다. 지난달에 뒤늦게 추가·수정된 항목은 별도 보고한다.
동일 자료 재실행 시 레코드를 중복 생성하지 않으며 변경이 없으면 쓰기를 생략한다.
새 월이나 새 원본 버전으로 전환할 때는 백업 식별 정보와 변경 없는 상세의 연결도 확인한다.
확인이 필요한 상황에서는 임의로 저장하거나 대화 응답을 계속 기다리지 말고,
쓰기 전 검증 단계에서 확인 필요로 종료하고 원인과 필요한 조치를 보고한다.
쓰기 도중 실패했다면 완료 처리하지 말고 부분 반영 범위와 재개 정보를 보고한다.
대시보드 기능은 기존 것을 사용한다. 로컬 스크립트·직접 SQL·소스코드 접근은 사용하지 않는다.
```

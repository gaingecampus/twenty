title: Create Many-to-Many Relations
description: Connect relationship records where many items on both sides can be linked together using junction objects.
---

Many-to-many relations let you connect multiple records on both sides. For example: many People can work on many Projects, and each Project can have many People.

<Warning>
**Beta Feature**: Junction relations are currently in beta. Enable them at **Settings → Community → Features** before following this guide.
</Warning>

## When to Use Many-to-Many

Use many-to-many when both sides of a relationship can have multiple connections:

| Relationship | Example |
|-------------|---------|
| People ↔ Projects | A person works on multiple projects; a project can have multiple team members |
| Companies ↔ Tags | A company can have multiple tags; a tag can apply to multiple companies |
| Products ↔ Orders | A product can be in multiple orders; an order contains multiple products |

## How It Works

Twenty uses a **junction object** pattern for many-to-many relations. A junction object sits between two objects and holds the connections:

```
People ←→ Project Assignments ←→ Projects
```

When you create a **Many to many** relation from Settings, Twenty:

1. Creates the junction object automatically
2. Adds the relation fields on both sides
3. Configures the UI to show the final linked records (not junction rows)

The junction object still exists and stores the connections, but the record UI presents a cleaner many-to-many view.

## Prerequisites

1. **Enable Junction Relations in Beta Features**: Go to **Settings → Community → Features** and enable **Junction Relations**

## Quick path: One-click Many to many

1. Go to **Settings → Data Model**
2. Open the source object (e.g. **Companies**)
3. Click **+ Add Relation**
4. Set **Relation type** to **Many to many**
5. Choose the destination object (e.g. **People**)
6. Set:
   - Field name on the source object (e.g. "Team members")
   - Field on destination object (e.g. "Companies")
   - Optional junction object name (auto-generated if empty)
7. Click **Save**

### Result

- On a **Company** record, the field shows **People** directly
- On a **Person** record, the reverse field shows **Companies** directly
- Selecting or clearing a record creates or deletes a junction row under the hood
- A unique composite index on the junction join columns prevents duplicate links

## Advanced path: Manual junction configuration

If you need extra fields on the connection itself (role, start date, etc.), or you already created a junction object, use Advanced mode.

<Note>
This path also requires **Advanced mode** (toggle at the bottom left of Settings).
</Note>

### Step 1: Create the Junction Object

1. Go to **Settings → Data Model**
2. Click **+ New object**
3. Name it descriptively (e.g. "Project Assignment")
4. Toggle "Skip creating a Name field" on
5. Click **Save**

### Step 2: Create Relations Between Objects and the Junction

Add **Has many** relations from each of your two objects to the junction object.

### Step 3: Configure the Junction Relation Display

1. Edit each **Has many** field that points to the junction object
2. Enable **"This is a relation to a Junction Object"**
3. Select the **Target relation** on the junction (the field pointing to the other side)
4. Click **Save**

## Adding Extra Data to Connections

Since the junction object is a real object, you can add custom fields to store information about the relationship:

- **Role**: "Developer", "Designer", "Manager"
- **Start Date**: When they joined the project
- **Hours Allocated**: Weekly hours on this project

To access this data, navigate to the junction object directly or query it via the API.

## Deleting a Many-to-Many Relation

- Deleting the relation field removes the relation pair (and its inverse join field).
- The junction object and its records are **not** deleted automatically.
- Delete the junction object separately from **Settings → Data Model** if you no longer need the connection data.

## Permissions

Creating a many-to-many relation creates a normal custom junction object. Workspace roles that can create/read/update/delete records on that object can manage links. Adjust object permissions if needed after creation.

## Troubleshooting

If re-selecting a previously removed link shows **"This record already exists"**:

1. Make sure the app is running the latest version (junction unique indexes use `WHERE "deletedAt" IS NULL`)
2. Unselect and select the record again — the UI repairs the junction index automatically on retry
3. Or call the metadata mutation `repairManyToManyJunctionUniqueIndex` with the junction object id

## Limitations

- **CSV Import/Export**: Importing many-to-many relations directly is not supported. Import records to the junction object instead.
- **Filters**: Filtering by many-to-many relations may have limited options.
- **Self-relations**: Many-to-many relations to the same object are not supported in the one-click flow.

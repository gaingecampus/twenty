# 계약 종료일 경과 시 온보딩 자동 종료

gainge-crm 운영 워크플로: `c1f51133-b3b1-4045-b18b-539168be3eb5`
버전: `2d5fa222-871d-4edd-914a-842a1ba622d8`

상태: ACTIVE. 2026-09-11 사용자가 기존 종료일 경과 계약도 포함하는 활성화를 승인했고, 운영 MCP로 활성화 후 재조회했다. 이후 사용자 요청으로 한국 시간 오전 3시 일정의 v2를 활성화했다.

- 매일 18:00 UTC (한국 다음 날 03:00), 종료일이 UTC 오늘보다 이전인 ACTIVE 계약을 조회한다.
- 계약 종료일 당일, 종료일 미입력, PRE, DONE은 제외한다.
- 조회한 계약별로 `onboardingStatus`만 `DONE`으로 변경한다.
- 조회 제한은 200건. 초과분 및 실패 후 남은 ACTIVE 계약은 다음 실행에서 재처리한다.
- 실패 시 재시도하며, 실패한 계약을 건너뛰어 성공으로 처리하지 않는다.
- 2026-09-10 기준 기존 대상은 33건이었다. 이후 사용자는 기존 계약도 예약 실행에 포함하도록 승인했다. 별도의 즉시 일괄 실행은 수행하지 않았다.

주의: FIND_RECORDS의 날짜 필터는 현재 코드에서 UTC를 사용한다. 오전 3시 KST에는 UTC 날짜가 전날이므로, 한국 날짜 기준 전날 종료 계약은 그날 실행에서 제외되어 하루 늦게 처리될 수 있다. 예: 9월 11일 종료 계약은 9월 12일 03:00 KST에 제외되고 9월 13일 03:00 KST에 포함된다. 스케줄만 변경한 현재 운영 상태를 이 정의에 보존했으며, 한국 날짜 기준 필터 보정은 별도로 필요하다.

검증: gainge-crm `validate_workflow` 통과. 저장소의 실제 `computeRecordGqlOperationFilter`로 ACTIVE 조건과 DATE의 엄격한 이전 날짜 비교가 결합되는 것을 확인했다. 최초 조회가 이전 단계 변수를 사용하지 않는다는 경고는 예약 실행의 독립 조회이므로 정상이다. 예약 실행 자체의 성공 이력은 아직 없다.

재생성 정의는 `onboarding-auto-complete.workflow.json`에 보관한다. 운영 워크스페이스의 필드 ID가 포함되어 있으므로 다른 워크스페이스에 적용할 때는 ID와 스케줄 시간대를 다시 확인해야 한다. 기존 워크플로가 있으므로 정의를 그대로 다시 생성하지 않는다.

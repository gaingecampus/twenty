# 문의 단계별 도달 소요일

로컬 구현 및 API·현황판 검증 완료. 운영 메타데이터 생성·트리거 설치·프론트 배포는 아직 하지 않았다.

## 측정 규칙

- 운영 `customStage` 8개 옵션별로 최초 **관측** 도달 시각과 생성일부터 누적 소요일을 저장한다.
- 한국 날짜 기준 일수이며 주말 포함, 같은 날은 0일이다. 영업일이나 정확한 24시간 단위가 아니다.
- 최초 측정 시 생성일을 `stageTimingOriginAt`에 고정한다. 이후 생성일 편집으로 기존/신규 지표 기준이 달라지지 않는다.
- 돌아온 단계는 최초 값을 유지한다. 건너뛴 단계는 비운다. 상태가 바뀌지 않는 편집은 측정하지 않는다.
- 기존 문의의 과거 단계는 추정하지 않는다. 설치 후 관측한 변화만 측정하므로 기존 문의의 실제 생애 최초 도달일이라고 단정할 수 없다.
- 생성 시 현재 단계만 기록한다. 과거 날짜로 수입한 문의도 실제 관측 시각을 사용한다. 미래 생성일로 음수가 되는 경우는 비운다.
- 삭제/복원은 단계 전환으로 취급하지 않는다. 기존 `matchingSuccessAt` 자동화 2개와 별개 필드를 사용한다.
- 현재 단계 체류일과 직전 단계 전환 소요일은 이 초안 범위 밖이다. 사용자 측정 기준 답변에 따라 변경할 수 있다.

## 자동화 방식

CRM CODE 워크플로우는 운영에서 비활성화되어 있어 계산을 별도 비동기 워크플로우에 의존시키지 않는다. PostgreSQL 행 트리거로 상태 변경과 계산값을 같은 트랜잭션에 저장한다. API·UI·일괄 업데이트에도 동일하게 적용한다. 조회 후 별도 갱신 경쟁과 재귀 이벤트를 피한다.

18개 사용자 정의 필드는 `schema.mjs`의 manifest를 CRM 메타데이터 API로 생성한다. 기존 동명 필드 유형을 검증하고, DB와 API의 워크스페이스가 일치하는지 확인한다. 기존 문의 데이터는 업데이트하지 않는다. 트리거 설치는 짧은 잠금 시간 제한으로 수행하며 실패하면 롤백한다. 메타데이터 생성 도중 실패하면 생성된 빈 필드는 남고 재실행으로 이어간다.

기존 동일 이름 필드가 다른 용도로 사용된 적이 있으면 설치하지 않는다. 메타데이터 변경/필드 이름 변경/복원 작업 시 이 트리거 의존성을 함께 검토한다. 자동 계산 필드를 사용자가 직접 바꿔도 DB에서 기존 값을 유지한다. UI 읽기 전용 권한은 운영 역할 정책에 맞춰 추가 설정해야 한다.

## 현황판

`/status-board`에 전체 기간 기준 단계별 평균 일수와 측정 건수를 표시한다. 기존 그룹/담당자 선택을 따른다. 측정값이 없는 건은 평균에서 제외하고 0일은 포함한다. 카드 클릭으로 측정 대상 문의와 해당 단계 소요일을 확인한다. 단계 칼럼 읽기 권한이 없거나 설치 전이면 관련 집계를 요청하지 않는다. 기간 필터와 혼동하지 않도록 전체 기간 기준을 명시한다.

## 설치 및 검증

환경 변수 `PG_DATABASE_URL`, `CRM_API_URL`, 적용 시 `CRM_ACCESS_TOKEN`을 보안 런타임에서 제공한다. 대화/로그/저장소에 인증값을 넣지 않는다.

```sh
# 먼저 읽기 전용 계획 확인. 실제 workspace UUID 사용.
node --experimental-strip-types packages/twenty-server/scripts/opportunity-stage-timing/install.mjs --workspace-id=WORKSPACE_UUID
# 확인한 같은 대상에 메타데이터와 트리거 설치
node --experimental-strip-types packages/twenty-server/scripts/opportunity-stage-timing/install.mjs --workspace-id=WORKSPACE_UUID --apply
# 로컬 DB에서만 수행하는 격리 트랜잭션 테스트(끝나면 전체 롤백)
node --env-file=packages/twenty-server/.env --experimental-strip-types --test packages/twenty-server/scripts/opportunity-stage-timing/trigger.test.mjs
```

운영 설치 전에 로컬 CRM 메타데이터 생성·API 변경 응답·현황판 렌더링을 검증해야 한다. SQL 통합 테스트만으로 이 전체 경로를 검증했다고 간주하지 않는다. 2.20.0 workspace upgrade에 설치를 등록했다. 정식 배포 시 필드 생성 후 트리거를 설치하며 기존 문의를 일괄 갱신하지 않는다. 수동 설치 스크립트는 진단·복구용으로 유지한다.

## 검증 결과 (2026-09-08)

- 로컬 메타데이터 API로 18개 필드 생성 및 트리거 설치 완료.
- 격리 PostgreSQL 통합 테스트 2개 통과(생성, 재진입, 건너뛰기, 일괄 변경, 한국 날짜 경계, 소프트 삭제/복원).
- 로컬 API로 생성 후 5일 된 검증 문의 생성 및 제안 단계 변경: 두 단계 소요일 5일 반환 확인. 현황판 평균 5.0일·측정 1건 및 상세 목록 제안 도달 5일 표시 확인. 검증 문의는 API로 소프트 삭제 완료.
- 프론트 전체 타입 검사: 변경 파일 오류 없음. 기존 다른 파일의 타입 오류 6개로 전체 검사는 실패하므로 배포 전 별도 해결 필요.
- 공유 상수 빌드 통과.

- Jira: AX-209. 정식 workspace upgrade 명령 로컬 실행 및 서버 SWC 빌드 통과.
